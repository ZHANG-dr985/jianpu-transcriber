# MP3 扒简谱工具（88 键电子琴版）

把一段 MP3 / WAV 音频自动扒成**简谱**，排版严格照着参考谱《花又落》
（1=C、2/4、大谱表、圆圈指法、〔小节号〕、页码 n/N）制作，输出 PNG / PDF / 可编辑文本 / MIDI。

> 版式不是“类似”，而是按参考图逐像素测量后复刻的：
> 页面 1080×1440、标题宋体居中、左上 `1=C`、每行 3 小节、每页 4 行、
> 左侧花括号与两处 2/4 拍号、数字上方圆圈指法、上下八度点、减时线（八分/十六分）、
> 附点、增时线 `-`、连音线/延音线、行首小节线、行尾双纵线、页脚 `n/N`。
> 自检里用参考图做了墨量、小节线坐标、音符 x 坐标、减时线 y 坐标的对比，误差都在 2~3 像素内。

**功能一览**

- 音频 → 简谱：ffmpeg 解码 + STFT 谐波显著性 + Krumhansl 调性识别 + 起始点/自相关估速
- 主旋律提取：Viterbi 连续音高跟踪（或 onset 分段）+ 八度纠正，量化到十六分音符栅格
- 左手伴奏：按小节做和弦模板匹配，生成与参考谱同型的分解和弦音型
- 88 键指法：右手动态规划分配 1~5 指，左手固定音型指法
- 输出：PNG（1080×1440 分页）/ PDF / 可编辑简谱文本 / 逐音对照表 / 双轨 MIDI
- 改谱不用重扒：直接编辑 `.jianpu.txt` 后重新排版即可

## 0. 快速开始

```powershell
git clone https://github.com/<your-name>/jianpu-transcriber.git
cd jianpu-transcriber
pip install -r requirements.txt          # numpy + Pillow
# 另需安装 ffmpeg 用于音频解码，并确保 ffmpeg.exe 在 PATH 中
python app.py                            # 启动图形界面
```

命令行批量用法：

```powershell
python cli.py --input "D:\music\花又落.mp3" --outdir "D:\music\简谱" --title "花又落"
```

## 1. 运行环境

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10/11（图形界面依赖标准库 `tkinter`；核心算法跨平台） |
| Python | 3.10 及以上，第三方依赖见 `requirements.txt`（`numpy`、`Pillow`） |
| 音频解码 | `ffmpeg`（优先从 PATH 查找，也会尝试 `C:\ffmpeg\bin\ffmpeg.exe` 与解释器同目录） |
| 字体 | Windows 自带 `times.ttf`、`simsun.ttc` 即可；其他系统需自备字体并调整 `jianpu/render.py` 中的字体路径 |

不需要联网，也不需要 librosa 等重型音频库。

## 2. 怎么用

### 2.1 图形界面
```powershell
python app.py
```
（也可以双击仓库内的 `启动扒谱工具.bat`，如本机 Python 不在默认位置，请修改该 bat 或 `app.py` 顶部的候选路径。）

1. 「选择音频…」挑一个 mp3；
2. 曲名会自动填上文件名（可改）；
3. 右边参数一般不用动（默认 `1=自动`、`2/4`、`速度自动`）；
4. 点 **「开始扒谱」**，等进度条走完；
5. 「排版预览」里就是排好版的简谱，可翻页；默认 1:1 显示（可拖动/滚动），
   点 **「适应宽度」** 可整行缩放（再点一次还原 1:1）；
6. 「打开输出文件夹」拿到 PNG / PDF / 文本 / MIDI。

### 2.2 命令行（批量或脚本用）
```powershell
python cli.py --input "song.mp3" --outdir "out" --title "花又落"
python cli.py --render-text "out/花又落.jianpu.txt" --outdir "out2"
```
运行结束会打印一行 JSON（界面就是靠它通信的），关键字段：
`ok / message / outdir / files{png,pdf,text,table,midi} / key / bpm / meter / measures / notes / preview / warnings`

常用参数：

| 参数 | 说明 |
|---|---|
| `--key auto\|C\|D\|bB…` | 调性，默认自动识别 |
| `--meter auto\|2/4\|3/4\|4/4` | 拍号，默认 `2/4`（与参考谱一致） |
| `--bpm auto\|数字` | 速度；自动会有“快一倍/慢一倍”歧义时用数字强制 |
| `--melody-range G3-E6` | 主旋律音域，缩小范围能显著减少伴奏串入 |
| `--sensitivity 0..1` | 灵敏度，默认 0.5 |
| `--engine viterbi\|onset` | 主旋律提取算法，默认 viterbi；伴奏很满时试试 onset |
| `--tempo-prefer slow\|fast\|none` | 速度读法倾向，默认 slow |
| `--no-bass` | 只出主旋律，不生成左手伴奏 |
| `--measures-per-line 3` | 每行小节数（参考图是 3） |
| `--systems-per-page 4` | 每页行数（参考图是 4） |
| `--formats "png,pdf,txt,midi"` | 输出格式 |
| `--render-text 文本.txt` | 把手工改过的简谱文本重新排版 |

## 3. 输出文件

| 文件 | 内容 |
|---|---|
| `曲名_1.png …` | 排版好的简谱图片（一页一张，1080×1440） |
| `曲名.pdf` | 上面所有页合成的 PDF，可直接打印 |
| `曲名.jianpu.txt` | **可编辑**的简谱数据（改完用「按修改重新排版」或 `--render-text` 再生成图） |
| `曲名.对照表.txt` | 逐音对照：第几拍 / 音名 / 简谱写法 / 八度点 / 时值 / 左右手指法 / 88 键第几键 |
| `曲名.mid` | 双轨 MIDI（0=右手旋律、1=左手伴奏），每个音前带指法文本标记，可导入编曲软件 |

### 文本微调格式
```
[小节号] chord=和弦
M 起拍:音:时值 起拍:音:时值 …
B 起拍:音:时值 …
```
音 = `级数[#/b][+/-八度][@指法]`，例如：

| 写法 | 含义 |
|---|---|
| `0:5@1:0.5` | 第 0 拍、简谱 5、一指、半拍 |
| `1.5:3+@5:0.5` | 第 1.5 拍、高八度 3、五指、半拍 |
| `0.75:#4:0.25` | 第 0.75 拍、升 4、十六分音符 |
| `1-:2-:1` | 低八度 2、一指、一拍 |
| `0:0:1` | 休止一拍 |

## 4. 扒谱流程与参数建议

```
解码(ffmpeg→22.05kHz 单声道)
   → STFT + 谐波求和显著性(Harmonic Sum Salience)
   → Krumhansl 模板识别调性
   → 起始点谱通量 + 自相关估速 + 强拍定位
   → 主旋律提取（Viterbi 连续跟踪／起音分段）+ 八度纠正
   → 量化到十六分音符栅格 → 简谱时值/八度点/减时线
   → 按小节做和弦模板匹配 → 左手八分/十六分分解音型（与参考谱同型：根 五 根 三 五 三 根 五）
   → 右手指法动态规划 + 左手固定音型指法
   → Pillow 排版出图
```

**提高成功率的经验**

* 独奏、清唱、主旋律突出的歌 → 基本一遍就准。
* 编曲很满（钢琴伴奏写得跟参考谱一样密）→ 主旋律在长音处可能被伴奏“带跑”，
  表现为长音后面多出几个小音符。两个办法：
  1. 把 `--melody-range` 收到实际人声音域（例如 `C4-C6`）；
  2. 换成 `--engine onset` 再试一次。
* 速度识别成两倍/一半时 → 用 `--bpm` 直接写数字（每个音符“应该”是一拍，
  四二拍一小节 2 拍；参考谱的左手是一拍四个十六分音符）。
* 结果不满意不用重新扒：直接改 `.jianpu.txt`，再 `--render-text` 重新排版，几秒钟出新图。

## 5. 88 键指法

* 音高范围限制在 `A0(21) ~ C8(108)`，超出会提示“超出 88 键”。
* 右手旋律：动态规划分配 1~5 指，代价包含手指移动距离、跨指、同指异音、
  黑键上避免拇指/小指；与参考谱第 1、3 小节的实际指法 ①⑤④⑤、①②③④ 完全一致。
* 左手伴奏：与参考谱相同的分解音型，指法用 5-2-1-2-1-2-1-2（参考谱实际记法）。
* 指法是**算法建议**，同一句往往有多种合理指法，可按自己习惯在文本里改 `@数字`。

## 7. 自检 / 验收

```powershell
python tests/acceptance.py   # 交付验收：38 项一次跑完
```

## 8. 已知限制

1. **自动扒谱不是 100% 准确**。单声部/主旋律突出的素材很好，满编钢琴曲会串入伴奏音。
   本工具定位是“快速出可用的初稿 + 方便手工微调”，不是替代人工记谱。
2. **速度二义性**：60 与 120、72 与 144 在自相关上同样强。默认偏向“较慢的读法”
   （旋律记成八分音符，与参考谱一致），不满意就用 `--bpm` 指定。
3. 不支持鼓/打击乐的记谱；纯打击乐素材识别结果没有意义。
4. 和弦按小节用三和弦模板匹配（大调/小调音阶内的七级三和弦），
   左手音型与参考谱一致（分解和弦十六分音符），不是原曲伴奏的真实转写。
5. 只输出单声部旋律（主旋律），不拆分和声声部。
